# MT Nightshift — application style

© Mayanktaker Computers & Web Development | https://mayanktaker.com

The Qt Widgets application style is a separate package (`application-style/`, the
`MTNightshift` QStyle key), so its specification lives here rather than in
[`design.md`](design.md). `design.md` links to this file from §13 and keeps the
shape rules shared with the rest of the suite (§6), the palette (§2) and the
interaction-state vocabulary (§4).

Verification lives in [`validation.md`](validation.md); the offscreen probe that
renders every state through the built plugin is `tools/style-probe/check-style.py`.

## Overview

`application-style/` provides the `MTNightshift` QStyle key. It is an original `QProxyStyle` over the installed Breeze QStyle: controls receive a shared 10px maximum corner radius, clamped for small widgets, while labels, icons, layout and unhandled primitives remain delegated to Breeze. Colors come from the active Qt palette so each MT scheme supplies its own surfaces and states. The field family uses borderless filled surfaces with a quiet hover outline and stronger focus ring: framed line edits, combo boxes in both states (editable ones take the input `Base` tone, menu-style ones the `Button` tone) and spin boxes (`CC_SpinBox`, with hand-drawn chevron and plus/minus glyphs so a hit step limit can mute its own arrow, which Breeze's generic arrow primitives cannot express). Frameless plain edits stay with Breeze, and the child editors of combos and spin boxes paint nothing so they sit on the container's rounded surface. KIO path bars are handled separately: `KUrlNavigator` (and Dolphin's subclass) paints itself through `PE_FrameLineEdit`, not `PE_PanelLineEdit`, so the style intercepts that primitive for any widget whose meta-object chain contains the public class name `KUrlNavigator` and fills the same rounded surface from the widget's `Base` tone. That covers Dolphin and other KIO file dialogs without app-name coupling. App-initiated draws that pass a QLineEdit widget to `PE_FrameLineEdit` are suppressed, so Breeze's tight-radius frame can never stamp over the pill `PE_PanelLineEdit` painted; every other widget drawing the primitive keeps Breeze's frame. The navigator sets `State_HasFocus` only while editing or with its context menu open, so the accent ring appears in those states only. The Dolphin Places dock separator is suppressed only in Dolphin's main window, while the dock remains resizable. The thin horizontal toolbar/window-background hairline remains because Qt/Breeze paints it in a broader background pass; removing only that row would require a fragile buffered repaint.

The plugin affects Qt Widgets applications and QQC2 Desktop Style delegate items; other Qt Quick/Kirigami apps and Plasma's own controls use separate styling systems. The `.themerc` file provides the System Settings display name; the plugin and metadata are installed in `/usr/lib64/qt6/plugins/styles/` and `/usr/share/kstyle/themes/`. The Global Theme selects `MTNightshift` as `widgetStyle`. Rebuild after Qt ABI updates.

**Restart the app, not just the window:** a style is resolved once per process, and Dolphin reuses its existing window, so `dolphin` on a running instance shows the old style. `make style-preview APP=<app>` runs any app against the freshly built plugin through `QT_PLUGIN_PATH`, which is also the only check available where the plugin is not installed system-wide.

The path bar reads as a filled Sculpted field, not a Breeze frame: KIO tints a URL navigator's own `Base` to the toolbar shade, so the style takes the input tone from the application palette instead. Without that the fill matched the toolbar exactly and only the corner antialiasing hinted at the field, which looked like a broken corner radius rather than a rounded field. App tooltips are styled too (`PE_PanelTipLabel`, `kTipRadius` 10px from `design.md` §6, `ToolTipBase` fill, 1px frame): Breeze's default is a square-cornered frame, which showed up as a stray bordered box wherever a tooltip appeared over the view. The focus ring is 1px everywhere (fields and buttons share one weight constant); its visibility comes from the WCAG 5:1 contrast token rather than stroke weight, which reads crisper on a 1x display than the earlier 2px ring. Dolphin's compact status card (the item-count box, `ShowStatusBar=Small`) paints its own Window-tone rounded fill and asks the style for a square `PE_Frame`; the style answers with a hairline that follows the card's 5px rounding inside Dolphin's own clip, so the border can never square the corners off. The card's flat left/bottom edges are Dolphin's design — its clip cuts them — and since the card sits on the view's `Base` with only a subtle tone step and cannot be rounded further from a QStyle, the shipped configuration switches Dolphin to `ShowStatusBar=FullWidth`, whose standard strip Breeze already separates with the §6 `frameContrast` hairline.

The keyboard-focus indicator in item views is ours too: Breeze's squarish focus outline (its radius far tighter than the pill) stacked on top of the selection pill, so a selected-and-focused item showed a proper pill inside a boxy border. `PE_FrameFocusRect` now paints a 1px accent pill ring at the selection pill's own inset and radius, and is suppressed while the item is selected — the selection already announces it. Unselected keyboard focus keeps a visible ring for accessibility.
Kate's welcome page exposed the delegate-routed path: its recent-files and session lists go through `CE_ItemViewItem`, where Breeze paints its own square band and — for boxed views — a loud `Highlight` frame. The style intercepts `CE_ItemViewItem` (paints the pill, strips the band from Breeze's content rendering, recolours list text for contrast on the accent fill) and `CE_ShapedFrame` for item-view panels (dimmed rounded hairline instead of the blue square outline). A `PM_DefaultFrameWidth` floor of one pixel for boxed item views keeps their viewport from swallowing the frame.
