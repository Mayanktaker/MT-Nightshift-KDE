# Project map

- **Product:** MT Nightshift KDE theme set: Plasma Style, global color scheme, Plasma Look-and-Feel, Aurorae window decoration, and a Qt Widgets Application Style layered over Breeze.
- **Target environment:** Fedora Linux 45, KDE Plasma 6.8.2. The baseline was copied from `plasma-breeze-common` and `libplasma` 6.8.2-1.fc45.
- **Project type:** KDE theme assets plus a C++17 Qt Widgets plugin; CMake 4.3.0, ECM 6.31.0, Qt 6.11.2, DNF. No standalone application runtime.
- **Deliverables:** `themes/mt-nightshift/` (Plasma Style, ID `mt-nightshift`), `color-schemes/MT-Nightshift.colors`, `themes/mt-nightshift-global/` (Look-and-Feel ID `com.mayanktaker.mt-nightshift.desktop`), `themes/aurorae/MTNightshift/`, and `application-style/` (Qt style key `MTNightshift`). Four more variants reuse the same geometry and the one palette-driven plugin: Dayshift (`color-schemes/MT-Dayshift.colors`, `themes/mt-dayshift/`, `themes/mt-dayshift-global/`, `themes/aurorae/MTDayshift/`), Nord Night (`MT-Nord-Night.colors`, `mt-nord-night/`, `mt-nord-night-global/`, `MTNordNight/`), Nord Day (`MT-Nord-Day.colors`, `mt-nord-day/`, `mt-nord-day-global/`, `MTNordDay/`) and One Dark Pro (`MT-One-Dark-Pro.colors`, `mt-one-dark-pro/`, `mt-one-dark-pro-global/`, `MTOneDarkPro/`). The One Dark Pro palette is derived from Binaryify's MIT-licensed One Dark Pro; its verbatim license is `LICENSES/MIT.txt`. All packages are version 1.6.1; the plugin is unchanged.
- **Visual source of truth:** `design.md`. Current task state: `PLAN.md`; closed items and their evidence: `plan-archive.md`. Provenance and licensing: `README.md`. Measurement methodology and the suite's limits: `validation.md`. Optional desktop backgrounds and their generation prompts: `Wallpapers/README.md`.

## Working rules

- Keep `upstream/` unmodified. Put the new Plasma Style and global color scheme in separate project paths, with a unique MT Dark name and metadata.
- Follow `design.md` for palette, contrast, shape, and interaction-state decisions. Override only the Plasma assets needed; rely on Breeze fallback assets for unchanged elements.
- Preserve KDE contributor credits, embedded copyright/license notices, and per-file licensing. Do not imply KDE endorsement or relicense upstream assets.
- Test data packages through user-local KDE paths (`~/.local/share/plasma/desktoptheme/`, `~/.local/share/plasma/look-and-feel/`, `~/.local/share/color-schemes/`, `~/.local/share/aurorae/themes/`). The Qt style plugin has no user-local Qt search path on this host; system installation requires explicit approval. Record and restore active settings when live-testing.
- Validate metadata as JSON/Desktop Entry, SVG assets as XML, KPackages with `kpackagetool6`, and the Qt plugin with CMake plus an offscreen QStyleFactory smoke test. See `PLAN.md` for the verification sequence.
- Decoration artwork is generated for all five variants (`--variant nightshift|dayshift|nord-night|nord-day|one-dark-pro`, or `--all`; the palettes live in `VARIANTS`): edit `PARAMS` in `tools/decoration-probe/build-decoration.py` (padding, radius, header, shadow envelope, arc thickness — the frame colour is now the variant's explicit `frame_line` token, not a `PARAMS` mix) and regenerate; never hand-edit `decoration.svg` or the five button SVGs. Every `MT*rc`'s `Padding*` must equal its `padding`.
- `make check` runs the generator drift check for all five decoration and button sets, the raster checks (including Nord and One Dark Pro), SVG validation, `tools/decoration-probe/check-buttons.py`, `tools/theme-audit/check-theme.py` (package metadata, byte-identical palette copies and the 4.66:1/3:1 contrast floors for **all five** variants), `tools/wallpapers/build-wallpapers.py --check`, and the Qt style probe (`tools/style-probe`: renders the field family offscreen through the built plugin under all five schemes with per-variant reference tones and asserts the pill language, 1px ring, free-space meter and 12px scrollbar gutter; `check-style.py --ci` skips the Breeze-dependent assertions); `make apply` installs every variant and selects `VARIANT` (including the two steps Plasma does not persist: `[KDE] frameContrast` and KWin's cached `Padding*`). `make package` generates distributable KDE Store and user release tarballs under `dist/` via `tools/packaging/build-packages.py`. What each check measures, and what it cannot see: `validation.md`.
- `build/` is per-worktree. After merging a Qt style change into `main`, run `make style` **in the canonical checkout** before giving anyone a `sudo install` command: a worktree build can be older than the merged source, and installing it silently keeps the old behaviour. Compare `sha256sum build/style/mtnightshiftstyle.so` with the installed plugin after install.
- Live-session values are checked by `make verify-live VARIANT=<nightshift|dayshift|nord-night|nord-day|one-dark-pro>` (run by `make apply`, default `nightshift`; `apply-dayshift`, `apply-nord-night`, `apply-nord-day`, `apply-one-dark-pro` are aliases): `[KDE] frameContrast`, the active scheme/style/decoration, the deployed copies and the system plugin must all match the repo for that variant. `plasma-apply-lookandfeel` resets `frameContrast` on every run, so this drifts silently otherwise. Record the active values with `kreadconfig6` and restore them after live testing; this session's `[General] AccentColor` preference overrides Qt's selection fill, so a live pill is not the scheme's `Selection` tone.
- This Wayland session has no pointer-injection tool (`ydotool`/`kdotool`/`/dev/uinput` absent): drive windows through KWin global shortcuts over DBus (`org.kde.KWin` `/component/kwin`, `org.kde.kglobalaccel.Component.invokeShortcut`, e.g. `Window Maximize`, `Walk Through Windows`) and capture with `spectacle -b -n -o <path>`. AT-SPI actions do not focus `KUrlNavigator` here. This host has two 1920×1080 outputs (HDMI-A-1 at x=0, DP-1 at x=1920) and `spectacle -b -n -o` captures the full 3840×1080 virtual desktop. If the screen auto-locks, unlock with `dbus-send --session --dest=org.kde.screensaver /ScreenSaver org.kde.screensaver.SetActive boolean:false` (the `org.freedesktop.ScreenSaver` method alone does not release a locked session). Review window edges against a genuinely light wallpaper as well as a dark one; `plasma-apply-wallpaperimage` sets every output at once, so back up `~/.config/plasma-org.kde.plasma.desktop-appletsrc` first and restore it afterwards to keep the per-output wallpapers. Panel appearance is `[PlasmaViews][Panel 58] opacityMode` (1=Opaque); write it with `kwriteconfig6 --group PlasmaViews --group 'Panel 58' --key opacityMode --notify` and restore with `--delete`.
- After any `themes/aurorae/*/*.svg` change run `tools/decoration-probe/check-decoration.py` (also wired as a pre-commit hook via `git config core.hooksPath tools/git-hooks`). It builds its qsvg probe with CMake into `~/.cache/mt-nightshift-probe` (incremental), rasterises each slice and asserts the shadow/fill invariants; `design.md` §12.4 explains why element overlap and cutout masks break corners invisibly.
- Frame geometry is generated, never hand-edited: `tools/plasma-theme/round-panel-corners.py` (panel radius), `dialog-frame.py` (`dialogs/background` from Breeze's solid slices + the tooltip's 6px corners) and `applet-background.py` (`widgets/background`, the frame behind every popup: 14px, Breeze's 14px insets and shadow slices). All three `--check` runs are in `make check`. KSvg derives border size from the slice elements and content margin from the hint rects, so a corner smaller than its border gets stretched into a distorted arc.
- `make check` runs in CI (`.github/workflows/checks.yml`) and in the hook; `make check-dpr2` renders the artwork at 2x and proves the 1px-arc variant still holds the corner border on HiDPI. For a newly added variant, run the same probe explicitly: `python3 tools/decoration-probe/build-decoration.py --variant one-dark-pro --arc 1.0 build/one-dark-pro-dpr2.svg` then `./tools/decoration-probe/check-decoration.py --scale 2 build/one-dark-pro-dpr2.svg`.
- Review window edges on a **light wallpaper as well as a dark one**: the dark background hid a doubled shadow band and a wrong strip entirely, while a bright one exposed both.
